# レポートの突き合わせ（Next.js / TypeScript）

このリポジトリのバックテストが書くレポートJSON（`python -m backtest.run --report out.json`）を
2つ読み込み、**`result_digest` を計算し直して照合する**ビューア。
一致しない場合は、**入力・パラメータ・結果のどこが動いたのか**を葉の単位で示す。

```bash
npm install
npm run dev      # http://localhost:3000
npm test         # 43件（Python が書いた digest を独立に再計算して照合する）
npm run build    # 静的書き出し（out/）
```

## なぜ digest を計算し直すのか

レポートに書いてある `result_digest` をそのまま表示するだけなら、
**中身を書き換えたレポートも「一致」と表示される**。読む側が独立に計算して
初めて、その digest がその中身から出たものだと言える。

そのため、このビューアは Python 側（`backtest/report.py`）の正規化を
TypeScript で独立に実装している。**2つの言語が同じ digest を出せることが、
正規化の設計が言語に依存していないことの証明になっている。**

## 揃えるのが難しかった点

| | Python | 素直に書いた TypeScript | 対処 |
| --- | --- | --- | --- |
| **整数と実数の区別** | `45` はそのまま、`1220.0` は `"1220.000000"` | `JSON.parse` が両方 `number` にして**区別が消える** | JSONを自前で読み、`.` や指数の有無で種別を保つ（`lib/json-source.ts`） |
| **負のゼロ** | `-0.000000` | `(-0).toFixed(6)` は `"0.000000"` で符号が消える | `Object.is(value, -0)` で明示的に付け直す |
| **`inf` / `nan`** | 名前の文字列にする | `JSON.parse` は `Infinity` を**そもそも読めない** | 書き出し側で文字列へ落とす（`_json_safe`）。読む側も数値としては受け付けない |
| **鍵の並び** | `sorted()`＝文字列順 | JSの実行時は「整数に見える鍵」を数値順で先に置く | 自前で直列化し、コードポイント順で並べる |
| **大きすぎる実数** | `%f` は常に展開する | `toFixed` は 1e21 以上で指数表記へ切り替わる | **例外にして止める**（違う digest を静かに出すより良い） |

いずれも「動くが、ときどき違う答えを出す」形の食い違いで、
**テストが無ければ気付けない**種類のものである。

## 見本と、2言語をまたぐ番人

`fixtures/` は Python 側が生成する（`python -m scripts.make_web_fixtures`）。
整数・整数値の実数・負のゼロ・`inf`・`null`・非ASCII・辞書のリストといった、
**正規化がずれやすい形**を意図的に集めてある。

- `tests/test_web_fixtures.py`（Python）… 見本が今の実装と一致しているか
- `lib/canonical.test.ts`（TypeScript）… 同じ見本から同じ digest を出せるか

**片方の正規化だけを変えると、必ずどちらかが落ちる。**

## このアプリが送信するもの

**何も送らない。** レポートの読み取り・digest の計算・差分の抽出はすべて
ブラウザの中で完結する（`crypto.subtle`）。サーバもデータベースも持たず、
静的書き出し（`output: "export"`）で動く。
